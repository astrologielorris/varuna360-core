# Core astrology calculations
pyswisseph>=2.10.0

# Timezone and date handling
tzdata>=2024.1
pytz>=2024.1
# core/nisarga_dasha.py imports dateutil.relativedelta at module level. Its
# absence does not stop the app booting — it fails later with "Error updating
# Nisarga dasha: No module named 'dateutil'", which is why it was missed.
python-dateutil>=2.8.0
# timezonefinder 8.x is what we actually run. The old ==6.0.2 pin was
# stale and broke fresh installs on Python 3.14 because it transitively
# required h3==3.7.7 (no wheels for Py3.14, source build fails on
# modern CMake). Upgrading to 8.x lets pip pull a modern h3 wheel.
# Do NOT pin h3 directly — timezonefinder picks the compatible version.
# <8.3: 8.3.0 (2026-08-19) split the ~60 MB dataset into a separate
# timezonefinder-data package, which the macOS Nuitka bundling
# (--include-package-data=timezonefinder) does not pick up — CI's own
# bundle gate then fails on both arches. Lift only together with the
# packaging scripts and a data-present check on every platform.
timezonefinder>=8.0,<8.3

# GUI framework. PINNED to the version every test runs on (development and the
# Linux build). 6.12.0 broke the macOS app built with Nuitka 4.0.7 (2026-10-26):
# Nuitka's PySide6 post-load hook could no longer import QCoreApplication, so
# the Qt plugin path stayed empty and the app aborted at launch with "no Qt
# platform plugin". Move this pin only together with a packaged-app launch
# check on macOS.
PySide6==6.10.1
shiboken6==6.10.1
qt-material>=2.14

# Image handling
Pillow>=10.0.0

# Geocoding
geopy>=2.4.0
# core/geocode_service.py points geopy at certifi's CA bundle so online place
# search works on machines whose system TLS store is missing or stale. pip
# normally installs certifi with requests anyway; declaring it makes the
# guarantee explicit instead of transitive.
certifi>=2024.2.2

# License validation
PyJWT[crypto]>=2.8.0
cryptography>=42.0.0

# HTTP requests
requests>=2.31.0

# Chart image AI import (core/chart_image_extraction.py). Imported inside the
# function, so a missing package only disables reading charts from an image
# with an Anthropic model; declared so source installs and the macOS build
# carry it.
anthropic>=0.40.0

# Deliberately NOT listed: claude-agent-sdk, mcp, anyio, jsonschema. They serve
# the AI capture, AI coach and MCP files, which Lite does not ship (SPEC-EDN-002
# INV-2, D-23); no Lite file imports them. They belong to the Pro build only.

# Process start time for the live-instance check (core/capabilities/
# live_state.py). Linux and Windows read it from the OS directly; macOS needs
# psutil, and without it the check falls back to the PID alone (a reused PID
# could then pass for a live app instance). macOS only.
psutil>=5.9; sys_platform == "darwin"

# --- libaditya: the calculation engine ---------------------------------
# github.com/ninthhousestudios/libaditya, installed from PyPI. EXACT pin:
# calculations change only when this line changes. libaditya declares its own
# requirements (pyswisseph, toml, more-itertools) and ships the Swiss
# Ephemeris files inside the package (libaditya/ephe/). Never ship a `git+` pin.
libaditya==0.4.4

# Varuna360's own direct use: core/toml_chart.py (SPEC-IMPORT-001 .toml).
toml>=0.10.0

# Voice input (td-mgcw8, Settings > Voice Input): numpy holds the microphone
# samples (ui/voice_dictation.py imports it at module level, so the app needs
# it to start), sherpa-onnx runs the speech model on the user's computer.
# Same pin as the development requirements.txt.
numpy>=1.26
sherpa-onnx==1.13.8

# Deliberately NOT listed: metar, rich, drawsvg, prettytable.
#
# Josh (libaditya's author) reported it as "silly that your app doesn't need
# metar or drawsvg or rich, but it won't run without them" — and he was right.
# All four sat behind MODULE-level imports in the engine (when it was vendored), so every
# user installed four packages to run features Varuna360 never calls:
#
#   metar        libaditya/objects/location.py — decodes airport weather
#                reports. Location is on the critical path for every chart,
#                which is the only reason this was ever loaded.
#   prettytable  __str__/__repr__ ASCII tables in objects/ and print_functions
#   rich         terminal-colour table rendering (objects/signs, calc/varga,
#                cards/, print_functions)
#   drawsvg      draw/draw_bodygraph.py + draw_sbc.py — Human Design SVG output
#
# Those imports are now function-level, so the packages are optional: the app
# boots and calculates without them, and only the specific CLI-print or
# SVG-drawing call that needs one would raise. They are registered in
# release_gates/check_requirements.py INTENTIONALLY_OPTIONAL with that reason.
#
# If you ever see one of them re-appear at module level, put it BACK here —
# at module level there is no degradation path, the app simply dies on start.
